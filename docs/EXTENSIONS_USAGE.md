# 扩展管理使用说明

## 入口与分类

- 设置 → 扩展，或会话侧栏 → 更多 → 扩展。
- **内置能力**：复用原工具能力页，查看手机工具与所需系统权限；原工具设置与旧路由仍保留。
- **已连接服务**：复用 MCP 连接列表与详情。添加服务地址和现有支持的 Bearer Token，不包含 OAuth、市场或本地 MCP 进程。
- **技能**：复用原技能导入和管理页。技能提供指导内容及资源，不授予工具权限，也不会自动启用依赖连接。

## 添加与使用远程连接

1. 添加连接，填写易区分的名称、MCP 地址和可选 Token。同一服务的不同账户应分别添加，名称建议包含“个人”“工作”等用途。
2. 添加时执行工具发现；连接成功与发现工具不代表任何新工具已授权。
3. 打开详情，查看缓存工具目录。在单项工具开关中查看服务提供的描述及输入参数定义，确认后授予该连接内此工具自动执行权限。服务声明的只读提示不是宿主验证。
4. 已授权工具在目标和运行入口约束内自动执行，不因写操作而逐次弹窗。未授权工具不执行；一次授权不覆盖其他工具、其他连接或账户。
5. 定义变化导致授权撤销后，查看新定义并重新授权。授权弹窗绑定打开时的连接代次；弹窗期间连接变更会要求关闭后重新查看，不能批准未看过的新定义。
6. 新启用能力可能需要发起新任务才能进入任务目录。工具总数仍受现有发现和每轮工具预算限制，页面保留超限提示。

## 本轮远程账户选择

宿主账户选择器已接入代码：当本轮候选远程连接多于一个时，在首次远程调用前弹出账户选择框，而不是仅凭模型选出的工具名决定账户。默认全部不选，用户可明确选择一个或多个连接；相同别名仍显示各自连接 ID。Runtime 仅在本轮缓存明确选择，选择不会启用工具或增加授权。

选择器只在当前运行会话的可见前台展示，最长等待 180 秒；拒绝、取消、超时、离开当前会话或前台均不批准目标。后台不会创建悬浮审批窗口。单候选路径不额外要求多账户选择，仍须经过原工具授权与入口检查。此行为尚未真机验收。

## 日历写入确认与操作核查

内置日历的创建、批量创建、更新、删除已接入逐次宿主确认代码，与远程 MCP 的“按工具授权自动执行”不同。确认窗口展示实际工具、连接/操作 ID、现有目标预览、规范化执行字段（包括日历/事件、起止时间、时区、提醒及批量各项）和到期时间，不只显示空白确认按钮。离开可见前台或当前会话会撤销待批准请求；已开始的操作不承诺回滚。

扩展页提供两个只读核查入口：

- **待核查的日历操作**：读取最多 100 条 UNKNOWN 元数据，较早记录优先；不重放，不把“没有记录”视为所有写入成功。
- **最近扩展调用**：读取最近 100 条本地调用记录，显示连接、工具、run/call 标识、代次、状态和耗时；不显示凭据、原始参数或返回正文，不触发网络或重试。

读取在 worker 线程执行。账本首次打开会执行已有的旧进程遗留状态恢复；界面没有修改、重试或确认成功按钮。UNKNOWN 表示已有副作用仍可能存在，应先核查目标，不能直接重建。审批及核查入口已接入代码，编译与相关定向测试已通过；尚无真机或真实服务端到端验收证据。

## 状态说明

列表区分连接启停、授权数量、缓存工具总数和最后成功检查工具的时间。缓存存在或检查成功不代表服务当前在线。没有检查记录时显示未知；刷新失败不把旧缓存时间更新为当前时间。

凭据更新未完成时显示调用阻止提示；请重新保存身份认证。保存失败不会把本次界面操作当作成功。现有数据没有定义变化原因、实时在线、持久认证失败分类或历史定义差异字段，因此页面不会虚构这些状态。

## 密钥、停用和删除

- 密钥输入框不读取或回显已保存的值。新输入以密码形式显示；取消或保存成功后清空。保存空值会移除身份认证，不是“保持不变”。
- 任务参数会发送给连接的远程服务。不要把连接管理当作手机本地执行保证。
- 关闭工具或连接只影响直接工具入口，不阻断终端、浏览器等通用工具访问同类数据。
- 停用和删除都不回滚已发生的副作用；已开始的远端动作仍可能完成。删除本地连接不等于撤销远端账户授权。

## 独立 HTTP MCP 验收夹具

`scripts/mcp-plugin-fixture/fixture.py` 仅使用 Python 标准库，数据仅存于内存；不会被 APK 引用或作为生产依赖。默认绑定 `127.0.0.1:8765`。

协议按当前 `McpHttpClient` 的实际请求形状实现：

- `/mcp`：`2026-07-28`，检查 `params._meta` 协议版本；目录返回 `resultType: complete`、`ttlMs`。
- `/legacy`：现代请求返回 400，供 AUTO 模式回退到 `2025-11-25` 的 initialize → session → initialized → tools/list/tools/call 流程；支持 DELETE 会话。会话绑定测试账户，不能跨账户复用。
- `/sse`：同样的 JSON-RPC 内容以 `text/event-stream` 返回。
- 工具原名为 `list_documents`、`search_documents`、`create_draft`；两个账户工具同名、数据隔离。草稿只留在夹具内存，不发送、不发布。

公开的夹具测试凭据是 `fixture-personal-only`、`fixture-work-only`；控制凭据是 `fixture-control-only`，均不是真实服务 Token。可通过 `FIXTURE_PERSONAL_TOKEN`、`FIXTURE_WORK_TOKEN`、`FIXTURE_CONTROL_TOKEN` 环境变量覆盖；不得填入真实服务凭据。服务不记录请求或授权头。

本地测试命令（使用绝对路径，不依赖当前目录）：

```sh
python -I -B E:/Desktop/AI研究/Eta-review-20261028/scripts/mcp-plugin-fixture/test_fixture.py
```

测试为每项用例短暂创建 loopback 临时端口 HTTP 服务，并在结束时关闭，不访问外部服务、不保留后台进程。若后续需要交互运行，必须通过开发预览工具启动 `python -I -B <绝对路径>/fixture.py`，不要在 Bash 启动常驻服务。本轮没有交互启动。手机不能直接访问电脑的 `127.0.0.1`；设备连接、端口转发和 Android 对测试 HTTP 的支持尚未验收。

### 操作者控制端点

`POST /control` 只接受独立控制凭据，控制操作不在 MCP 工具目录中，也不能交给示例 Skill。请求体为以下 JSON 之一：

```json
{"action":"add_tool"}
{"action":"change_definition"}
{"action":"fail_next","account":"personal","method":"tools/list","mode":"http_503"}
{"action":"fail_next","account":"work","method":"tools/call","mode":"after_write"}
{"action":"expire_sessions"}
```

- `add_tool` 增加 `count_documents`，用于验证刷新后新增工具不自动授权。
- `change_definition` 修改同名 `create_draft` 的描述与 schema，供宿主验证定义变化撤销授权。
- `fail_next` 是按账户和方法隔离的一次性故障；支持 `http_401`、`http_503`、`rpc_error`，调用还支持 `tool_error`、`after_write`。`after_write` 应配合下一次 `create_draft` 使用，先写入再返回 503，用只读查询确认副作用，不自动重放。
- `expire_sessions` 清除旧协议会话，供客户端会话重建测试。

夹具本身不实现 Theta 工具授权；它验证协议和隔离数据，不能单独证明 App 已执行授权、撤销或后台入口约束。它不模拟外部 OAuth、持久存储、全面 MCP 协议、分页、流式长连接或真实远端取消。

## 本轮检查与验收边界

新增 UI 状态投影的 JVM 回归测试覆盖停用后的授权数、未授权缓存、凭据更新阻止、未知检查时间和双连接独立计数。资源键与格式占位符已静态核对。Python 夹具 8 项 unittest 已通过，覆盖现代 JSON/SSE、旧协议会话和回退响应、双账户同名工具隔离、目录新增与变化、一次性故障、写后错误及输入校验。它们是标准库 HTTP 客户端到夹具的测试，不是 Android McpHttpClient 或整机端到端验收。
