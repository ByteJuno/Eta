# 后台虚拟屏（3.4.0-vscreen.1）

本 fork 采用上游 3.4.0 的 `agent/virtualdisplay` 引擎。设置中的「后台虚拟屏执行」使用 `agent_virtual_display_enabled`；Root 或 LSPosed system_server 增强可提供虚拟屏。胶囊包含实时预览、画布触控接管和全屏移交；旧 Root 虚拟屏、原生悬浮预览、独立查看页、自动重启及 `virtual_screen` 工具已删除。

## 路由与主屏许可

- 输入栏「虚拟屏」是默认选项：`launch_app` 与 `open_uri` 使用上游智能分流，跨应用任务优先虚拟屏；已经位于主屏前台的应用、桌面、SystemUI、Eta 和模型请求 `display=main` 仍选主屏。无后端或虚拟屏启动失败也可能选主屏。
- 启用虚拟屏后，上述任何路径在执行主屏 GUI 动作前，都必须取得本轮用户许可。Eta 内显示对话框，在其他界面显示授权悬浮窗，并以通知作为后备。模型请求主屏、聊天文字和开关本身均不算本轮授权。允许后只对该 run 有效；拒绝、超时、取消或无法显示授权界面，本轮不会执行主屏动作，也不重复申请。
- 截图、UI 树、等待查询、读取剪贴板及当前上下文等只读观察不申请许可。`present_to_user` 和胶囊全屏按钮是把画面交给用户，不需要主屏操作许可，也不授予后续自动操作的许可。移交、显示消失或人工接管后必须重新观察，旧节点和坐标不可重放。
- `open_system_panel`、HOME/RECENTS/通知栏/快捷设置按键以及写系统剪贴板均按主屏动作审批，即使上一画布是虚拟屏。无 Root 的虚拟屏 BACK 不调用作用于物理屏的无障碍全局动作，返回不可用。时钟工具原生一方接口不申请许可，只有需要启动系统时钟 Activity 时才走租约和主屏审批。
- 输入栏选择「主屏」表示用户已为该会话明确选择主屏：该会话不创建或启动虚拟屏，不再弹上述许可。选择仅影响后续运行，保存于 `eta_conversation_display_route`，未改变 Room。关闭虚拟屏功能时隐藏选择器，普通 GUI 走主屏。
- 自动任务可以使用受支持的后台虚拟屏工具，但不得兜底主屏；浏览器 GUI、终端命令及嵌套任务管理保持禁用。Shell、MCP 和终端的任意外部副作用不属于 GUI 租约的隔离保证，模型不得借这些接口绕过授权。

## 并发与接管

上游控制器只持有一个虚拟屏。主屏、虚拟屏和内置浏览器统一经过 fork 的 `AgentInteractionLease`，首次交互取得租约，持有到整轮结束（包括思考和暂停）；第二个会话等待且可以取消。没有引入上游 `GuiControlCoordinator` 或 `release_gui`。运行注册、事件与结果仍按会话独立。

胶囊只投影交互租约所属运行，等待者不能抢占胶囊。用户接管会暂停对应运行；恢复后旧观察失效。预览及截图捕获沿用上游 ImageReader，不创建第二块显示。

## 升级与兼容

从 3.3.5-vscreen.1 升级时，旧 DataStore `virtual_screen_enabled` 迁移到本地 Prefs：原来开启继续开启，原来关闭继续关闭；已有新 key 优先，不被迁移覆盖。新值落盘成功后删除旧 `virtual_screen_*` 配置，旧悬浮窗、自动重启、熄屏等许可不转移。没有旧值的新安装使用上游默认值。版本为 3.4.0-vscreen.1 / 2026103102，数据库仍为 28。

Root app_process 在 ActivityThread.systemMain 前补初始化 ApplicationSharedMemory，兼容 Android 15+。独立焦点与禁止抢顶层焦点使用上游 flags；独立显示组唤醒锁仅在 displayId 和 groupId 均大于 0 时尝试，ROM 拒绝则安全降级，不唤醒物理主屏。该兼容措施不承诺任意 ROM 的锁屏/熄屏运行；ColorOS 的 Root、LSPosed、预览触控与系统输入仍须真机验收。
