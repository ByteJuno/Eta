# 多会话执行

会话 A 运行时，可以新建或切换到会话 B 并发送消息；两轮请求独立执行。无需打开额外开关。

- 聊天、模型生成、搜索、HTTP 请求和终端工具可以跨会话并行。
- 同一会话仍只有一轮运行，追加消息按该会话自己的队列处理；完成其他会话不会阻止本会话继续队列。
- 输入框的停止和中断操作只针对当前选中的会话。前台执行通知的停止操作仍停止全部用户执行任务。
- App 界面关闭后重新打开，会查询所有在途运行并分别订阅事件与结果。系统终止执行进程后不会自动重放设备操作。
- 自动任务队列仍按现有调度器顺序处理，但不再因为另一个聊天会话正在运行而整体推迟。

## 共享资源

主屏、虚拟屏和内置浏览器属于共享交互环境。每轮第一次使用这些工具时申请交互资源，持有到该轮结束；其他需要交互资源的轮次等待。等待期间可以取消；取消正在执行的操作时，等操作退出后才移交资源。

这种安排保留同一轮内截图、点击、输入的连续性。两个会话无法同时控制同一个屏幕或内置浏览器；仅做文字或搜索的会话不受交互资源排队影响。

终端执行上下文按运行独立，但文件、Linux 环境和用户配置仍然共享，没有自动创建 Git worktree 或文件沙箱。两个会话修改同一文件时仍需由任务安排避免冲突。MCP 客户端按运行独立，远端资源是否可并行取决于对应服务；任意 shell 或远端工具不经过本地屏幕锁。

## 验收步骤

1. 在 A 发送一个持续生成的请求，切换到 B 发送另一个请求，确认两边均持续收到结果。
2. 在 A 追加消息，保持 B 运行，确认 A 完成当前轮后继续处理自己的追加消息。
3. 在 B 按停止，确认只有 B 停止，A 仍可继续；在空白新会话按停止不能停止其他会话。
4. 两轮运行中移除并重新打开 App 界面，确认两边各自恢复；不要强制停止应用进程。
5. A 使用屏幕/浏览器工具时，让 B 请求同类工具，确认 B 等待；取消 B，确认 A 不受影响。
6. 等 A 结束，确认下一轮可取得交互资源；检查虚拟屏/主屏回退和停止通知在实际 ROM 上的行为。

自动测试覆盖运行注册、独立恢复、IPC 列表兼容和交互资源的竞争/取消。APK 构建与签名验证不能替代上述真机验收。

## 渐进式同步上游

保留 fork 的整轮交互租约，不叠加上游 GuiControlCoordinator，也不在模型思考期间释放资源。
首次取得租约时清空本执行器的主屏和虚拟屏观察引用；在取得租约及宿主回调之后检查取消，避免等待者刚获得控制权就执行失效操作。
主屏回退仍需独立授权，路由切换后的旧观察不得重放。

等待状态显示在对应会话的聊天区域，不触发主屏悬浮层。浏览器页面按持久会话标识隔离，Cookie/网站存储仍共享；浏览器工具仍经过原有交互租约串行执行，不宣称浏览器操作完全并行。
会话页面由独立 Activity 展示；删除会话请求回收页面，正在运行或挂载的页面延迟回收，内存压力下仅回收空闲页面。运行取消只中断所属页面。
第一批和本批通过 CI 后方可合入 virtual-screen；测试通过不能替代 ROM 真机验收。
